## 💡 Overview
When integrating Large Language Models (LLMs) into applications, developers interact with models like OpenAI's GPT family or Anthropic's Claude family using **REST APIs** or official **Language SDKs** (Python/TypeScript). 

Understanding request structure, message roles, parameters, and payload parsing is critical for building robust, deterministic AI-native software.

---

## 📦 1. SDKs & Basic Request Structures

### A. OpenAI API Structure
OpenAI uses the **Chat Completions API** paradigm. You define messages as an array of structured objects.

#### Python Example (OpenAI SDK v1.x):
```python
from openai import OpenAI

client = OpenAI(api_key="YOUR_OPENAI_API_KEY")

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "You are a senior backend developer specializing in clean code."},
        {"role": "user", "content": "Explain how to implement Dependency Injection in Python with a brief example."}
    ],
    temperature=0.2,
    max_tokens=500
)

# Extracting response
output_text = response.choices[0].message.content
print(output_text)

```

---
### B. Anthropic API Structure
Anthropic's **Messages API** treats the `system` prompt as a top-level parameter rather than a message role inside the `messages` list.

#### Python Example (Anthropic SDK):
```python
import anthropic

client = anthropic.Anthropic(api_key="YOUR_ANTHROPIC_API_KEY")

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1000,
    temperature=0.1,
    system="You are a senior code reviewer. Provide concise, security-focused feedback.",
    messages=[
        {"role": "user", "content": "Review this SQL query: SELECT * FROM users WHERE username = 'admin' + input;"}
    ]
)

# Extracting response
output_text = response.content[0].text
print(output_text)
```

## 🎭 2. Message Roles & Prompting Architecture

An LLM conversation consists of three distinct roles:

| Role | Purpose | Example / Description |
| :--- | :--- | :--- |
| **`system`** | Sets global behavior, tone, output format rules, and hard boundaries. | *"Act as an API generator. Return ONLY valid JSON containing `status` and `data` keys."* |
| **`user`** | The dynamic input sent by the user or application trigger at runtime. | *"Extract entities from this email: [email_text]"* |
| **`assistant`** | Represents previous replies generated by the AI model. Used to pass context history in multi-turn conversations. | Stored in history array: `{"role": "assistant", "content": "The extracted entities are..."}` |

## ⚙️ 3. Key Request Parameters

Understanding parameter tuning is crucial for getting predictable output in software applications:

### 1. `temperature` (Range: `0.0` to `2.0` / `1.0` depending on API)
* **Low (`0.0` - `0.2`):** Highly deterministic, conservative, and repeatable. Best for **code generation, mathematical tasks, JSON extraction, and technical Q&A**.
* **High (`0.7` - `1.0+`):** Creative, varied, and exploratory. Best for **brainstorming, storytelling, and creative writing**.

### 2. `max_tokens`
* Defines the maximum number of tokens (words/sub-words) the model is allowed to generate in its response.
* **Why it matters:** Prevents infinite generation loops, controls API billing costs, and avoids HTTP timeout issues.

### 3. `top_p` (Nucleus Sampling)
* An alternative to `temperature`. `top_p=0.1` considers only tokens comprising the top 10% probability mass.
* *Best Practice:* Adjust either `temperature` OR `top_p`, but **not both** simultaneously.

## 📄 4. Handling Response Payloads & Structured Outputs

### A. Extracting Plain Text Responses
* **OpenAI:** `response.choices[0].message.content`
* **Anthropic:** `response.content[0].text`

### B. Enforcing Structured Output (JSON Output)
When building software, free-form text is hard to parse. Modern APIs allow enforcing strict JSON output schemas.

#### OpenAI Structured Output Example:
```python
from pydantic import BaseModel
from openai import OpenAI

class CodeReviewResult(BaseModel):
    has_vulnerabilities: bool
    vulnerability_type: str
    suggested_fix: str

client = OpenAI()

response = client.beta.chat.completions.parse(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "Analyze the user code for security bugs."},
        {"role": "user", "content": "eval(user_input)"}
    ],
    response_format=CodeReviewResult,
)

review = response.choices[0].message.parsed
print(f"Vulnerable: {review.has_vulnerabilities}")
print(f"Fix: {review.suggested_fix}")
```

## 🏗️ 5. Structuring Production-Grade System Prompts

A robust system prompt follows a modular structure:

1. **Role Definition:** Who is the AI?
2. **Context & Objective:** What is the specific goal?
3. **Constraints & Rules:** What MUST or MUST NOT be done?
4. **Output Format:** Exactly how should the output be formatted?

### Example Production System Prompt:
```markdown
You are an AI Code Security Auditor for an enterprise software delivery pipeline.

[TASK]
Analyze the provided code snippet for OWASP Top 10 security vulnerabilities.

[CONSTRAINTS]
1. DO NOT execute or run any code.
2. If no vulnerabilities exist, return an empty list for findings.
3. Be concise and precise. Avoid conversational filler like "Sure, I can help with that!".

[OUTPUT FORMAT]
Return a JSON object matching this schema:
{
  "status": "PASS" | "FAIL",
  "issues": [
    {
      "severity": "CRITICAL" | "HIGH" | "MEDIUM" | "LOW",
      "line_number": integer,
      "description": string,
      "remediation": string
    }
  ]
}
```

## 🎯 Quick Interview Prep QA

**Q1: How do you handle multi-turn conversations in OpenAI or Anthropic APIs?**  
> *Answer:* APIs are stateless. To maintain context, the application must store previous `user` and `assistant` messages in an array and pass the full message history in every new API request within the context window limits.

**Q2: What temperature would you set for generating unit tests vs. writing a creative essay?**  
> *Answer:* For unit test generation, set `temperature=0.0` or `0.1` to ensure deterministic, syntactically correct, and bug-free code. For creative essays, set `temperature=0.7` to `0.9` for variety and creativity.
